# Angle B — Last row / last column, wide terminals, ASCII degradation

Access date: 2026-10-03.

## Last-row / last-column

### WINNER: alternate screen buffer — bottom and btop both do this, unconditionally
- bottom `src/lib.rs` L367: `execute!(stdout_val, EnterAlternateScreen, EnableBracketedPaste)?;`
  (import L50). Source: https://github.com/ClementTsang/bottom (cloned cea7547)
- btop `src/btop_tools.cpp` L759-760:
  `const string Term::alt_screen = Fx::e + "?1049h";`
  `const string Term::normal_screen = Fx::e + "?1049l";`
  Source: https://raw.githubusercontent.com/aristocratos/btop/master/src/btop_tools.cpp
Mechanism: paint a full-screen buffer each frame into the alt buffer; no scrollback exists, so
the terminal never has to move the cursor past the bottom-right cell. No clamping needed.

### Reserve rows below the plot — plotext
`plotext/_settings/defaults.py` L9-14: `terminal = {..., "prompt height": 2, "limit width": True,
"limit height": True}`. `plotext/_kernel/terminal.py` L56-59:
```
def _update_size(self):
    width, height = self._get_total_size()
    height = max(0, height - self._prompt)
```
`terminal()` doc L35: "Set the prompt height (lines reserved below the plot)".
So plotext's plot grid is `terminal_lines - 2` tall by default.
Source: https://raw.githubusercontent.com/piccolomo/plotext/master/plotext/_kernel/terminal.py (200)

### Suppress the final newline — gnuplot dumb
`term/dumb.trm` L581 loops `for (y = dumb_ymax - 1; y >= 0; y--)`, and L612-613:
```
if (dumb_feed || y > 0)
    putc('\n', gpoutfile);
```
With `set term dumb nofeed` the trailing newline after the LAST row is suppressed, so output is
exactly `ychars` lines with no dangling newline. Exposed as `dumb_feed` (L161), default TRUE (L210).
Also L595: `if (*c != NUL) { /* Do not print cells occupied by wide characters. */ }` — the driver
skips the cell after a wide (East Asian) char. Directly relevant to any width-aware renderer.
Source: https://raw.githubusercontent.com/gnuplot/gnuplot/master/term/dumb.trm (200)

### gnuplot `block` `animate`
Doc: "resets the cursor position to the top left of the plot after every plot so that successive
plots overwrite the same area on the screen rather than having earlier plots scroll off the top."
Source: https://gnuplot.sourceforge.net/docs/loc19798.html

### No last-row awareness at all
spark, asciichart, termplot all return/print a string and leave the newline to the caller.
asciichart L107: `return result.map(x => x.join('')).join('\n')` — no trailing newline, caller
must add one. termplot L59: `print('')` after every row including the last.

### btop min-size, not last-row
`src/btop_tools.cpp` `Term::get_min_size(boxes)` returns the smallest viable width/height from
per-box `min_width`/`min_height`. It is a layout floor, not a scroll-avoidance clamp.
Resize via SIGWINCH handler `src/btop.cpp` L131-155 `term_resize()`.

## Wide terminals

| tool | behaviour | evidence |
|---|---|---|
| plotext | clamps plot to terminal (`terminal.limit` defaults True, `defaults.py` L13-14), then maps data x into the fixed-width plot matrix -> **stretches** | `terminal.py` L40-44, `defaults.py` L13-14 |
| asciichart | `width = max(series lengths) + offset` (L63-67). **Zero terminal awareness**, one column per sample, never resamples, never truncates | asciichart.js L63-67 |
| spark | one glyph per input number; no width logic at all | `spark` L67-71 |
| termplot | prints `len(x)` columns regardless; docstring explicitly warns output is inaccurate if data is longer than the terminal | term_plot.py L37-38 |
| btop | fixed 5x5 sub-cell per character, packs 2 samples per column | btop_draw.cpp L451-469 |
| gnuplot | caller sets it: `set term dumb size <xchars>,<ychars>`, default 79x24 | loc20689.html |
| bottom | ratatui `Layout::split()` divides the given `Rect`; width comes from the app | bottom src/canvas/* |

## ASCII / monochrome degradation

Verified by grepping `LC_ALL|LC_CTYPE|LANG=|getenv.*LANG|isatty` across every cloned repo
(2026-10-03):

- **plotext**: `plotext/_settings/system.py` L7 —
  `platform = "windows" if sys.platform in {"win32","cygwin"} else "unix"`.
  `plotext/_constants/enums.py` L46: `hd_markers_codes = ['hd','fhd','braille'] if platform == 'unix' else ['hd','braille']`.
  `high_def.cpp` L32: "These sextants ask for more room than a windows character has, so there the
  table holds blanks and is never read: fhd is not among the codes on windows".
  Trigger = **OS platform only**. No env var, no locale, no TTY check.
  Defaults L64-65 record the history: "version 5 used a single dot on windows, whose terminals
  could not always draw them". Confidence: primary.

- **btop**: manual user config only. `graph_symbol` = `braille|block|tty`, default `braille`
  (btop_config.cpp L50, L276). No auto-detection. A disabled `tty_mode` branch survives at
  btop_draw.cpp L435 (`// if (tty_mode and mult and i % 2 != 0) continue;`).

- **bottom**: manual CLI flag `--dot-marker` (src/options/args.rs L228-232) switches graphs
  from the braille marker to `•`. No auto-detection.

- **gnuplot dumb**: ASCII-first by design (`#` U+0023); Unicode is opt-in via
  `fillchar solid` = `"\U+2588"`.

- **asciichart**: `cfg.symbols` (L68) replaces the whole 10-entry glyph array -> ASCII possible,
  caller-driven.

- **visidata**: `disp_sparkline` is a `theme_option` (sparkline.py L9) so the ramp string itself is
  user-configurable.

- **bandwhich / spark / termplot**: nothing. bandwhich has no chart; spark and termplot have no
  fallback path.

**Conclusion: not one tool in this set degrades based on `LC_ALL`/`LANG`/`NO_COLOR`/TTY detection.**
Every fallback is either a platform check (plotext) or an explicit user flag/config.
btop CHANGELOG.md L616 mentions LANG/LC_ALL but only to blank them before a UTF-8 *search* —
unrelated to glyph choice.

## Gaps
- No tool in the set exposes a `NO_COLOR`-driven glyph fallback; if omp-stats-tui wants one it is novel.
- No primary issue thread found on any repo explicitly discussing the bottom-right cell; the
  alternate-screen approach makes the problem moot rather than being discussed, so absence of
  discussion is not evidence the problem does not exist.
